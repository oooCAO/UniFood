# UniFood

## Описание проекта
Веб-приложение для предварительного заказа еды
в столовых/кафе ГрГУ им. Янки Купалы
с последующим самостоятельным получением заказа.

## Функциональные требования

### Студент
1. Регистрация и авторизация
2. Просмотр заведений
3. Просмотр меню
4. Просмотр категорий
5. Просмотр информации о блюде
6. Добавление блюд в корзину
7. Изменение количества
8. Удаление блюд
9. Выбор места получения
10. Выбор времени получения
11. Оформление заказа
12. Просмотр статуса заказа
13. Просмотр истории заказов

### Сотрудник
1. Авторизация
2. Просмотр поступивших заказов
3. Просмотр состава заказа
4. Просмотр времени получения
5. Изменение статуса заказа
6. Подтверждение выдачи заказа

### Администратор
1. Управление пользователями
2. Управление заведениями
3. Управление категориями
4. Управление блюдами
5. Управление доступностью блюд
6. Управление временными слотами
7. Просмотр статистики

## Технологический стек

- PHP

Non-relational DB:

## Распределение данных между базами

MySQL (данные со связями и транзакциями):
- пользователи и роли
- заведения
- категории
- блюда и их доступность
- временные слоты
- заказы и состав заказов

MongoDB (гибкие и журнальные данные):
- история смены статусов заказов (когда и кем изменён статус)
- агрегированные данные для статистики администратора

## Организация разработки

### Команда
Проект разрабатывают три студента направления CS.
Разработка ведётся только с использованием агента OpenCode.
Код пишется в студенческом стиле, чтобы было видно, что проект создавали студенты.

### Стратегия ветвления (GitFlow)

Разработка ведётся параллельно по GitFlow.

- `main`: только стабильные версии, прямые коммиты запрещены
- `develop`: общая ветка разработки, прямые коммиты запрещены
- `feature/*`: создаётся от `develop`, одна ветка на одну задачу
- `release/*`: подготовка релиза от `develop`, затем слияние в `main` и `develop`
- `hotfix/*`: срочные правки от `main`, затем слияние в `main` и `develop`

Правила работы:
- слияние `feature/*` в `develop` только через Pull Request с ревью другого разработчика
- перед созданием Pull Request: `git pull origin develop` в свою ветку и разрешение конфликтов у себя
- каждый работает в OpenCode только в своей ветке и не меняет чужие файлы без согласования
- общие файлы меняет только их владелец

### Этапы разработки

1. **Этап 0:** каркас проекта и ветка `develop` (Разработчик 1)
2. **Этап 1:** авторизация, схема БД, общие стили и главная страница на заглушках
3. **Этап 2:** корзина и оформление заказа, админка (заведения, категории, блюда), меню и страница блюда
4. **Этап 3:** статус и история заказов, модуль сотрудника, слоты, пользователи, статистика, подключение реальных данных
5. **Этап 4:** интеграция, ручное тестирование, ветка `release/1.0`, слияние в `main`

Срок сдачи не определён, этапы указаны без дат.
