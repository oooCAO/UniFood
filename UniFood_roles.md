# UniFood: распределение ролей и ответственности

Проект: веб-приложение для предзаказа еды в столовых и кафе ГрГУ.
Стек: HTML5 / CSS3 / JavaScript (frontend), PHP (backend), MySQL + MongoDB.
Разработка: только через OpenCode, параллельно, по стратегии GitFlow.

Нумерация функций ниже берётся из README (Студент = С, Сотрудник = Сот, Администратор = А).

## Общая нагрузка

| Разработчик | Зона ответственности |
|---|---|
| Разработчик 1 | Ядро проекта, авторизация, оформление заказа студентом |
| Разработчик 2 | Модуль сотрудника, модуль администратора, схема баз данных |
| Разработчик 3 | Каталог для студента (просмотр), общие стили и страницы |

## Порядок работы (этапы)

1. **Этап 0 (Разработчик 1):** каркас проекта, ветка `develop`. Остальные ждут слияния `feature/project-skeleton` в `develop`.
2. **Этап 1 (параллельно):**
   - Разработчик 1: авторизация
   - Разработчик 2: схема БД
   - Разработчик 3: общие стили и главная страница на заглушках
3. **Этап 2 (параллельно):**
   - Разработчик 1: корзина и оформление заказа
   - Разработчик 2: админка (заведения, категории, блюда)
   - Разработчик 3: меню и страница блюда
4. **Этап 3 (параллельно):**
   - Разработчик 1: статус и история заказов
   - Разработчик 2: модуль сотрудника, слоты, пользователи, статистика
   - Разработчик 3: подключение реальных данных, доработка интерфейса
5. **Этап 4 (вместе):** интеграция, ручное тестирование, ветка `release/1.0`, слияние в `main`.

## Правила GitFlow для всех

- `main`: только стабильные версии. Прямые коммиты запрещены.
- `develop`: общая ветка разработки. Прямые коммиты запрещены.
- `feature/*`: создаётся **от `develop`**, одна ветка на одну задачу.
- Слияние `feature/*` в `develop` только через Pull Request с ревью другого разработчика.
- `release/*`: подготовка релиза от `develop`, затем слияние в `main` и `develop`.
- `hotfix/*`: срочные правки от `main`, затем слияние в `main` и `develop`.
- Перед созданием Pull Request: `git pull origin develop` в свою ветку и разрешение конфликтов у себя.
- Каждый работает в OpenCode только в своей ветке и не меняет чужие файлы без согласования.

## Как избегать конфликтов

- Каждый разработчик правит в основном свои файлы и папки (по зонам выше).
- Общие файлы (подключение к БД, общий `style.css`, роутинг) меняет только их владелец: Разработчик 1 для backend-ядра, Разработчик 3 для общих стилей.
- Если нужна правка в чужом файле, пишите владельцу, а не правьте сами.
