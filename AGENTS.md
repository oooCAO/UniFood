# UniFood: правила для агента

Этот файл читает OpenCode в начале каждой сессии. Правила обязательны для всех трёх разработчиков.

## О проекте

UniFood: учебное веб-приложение для предзаказа еды в столовых и кафе ГрГУ с самовывозом. Роли пользователей: студент, сотрудник, администратор. Полный список функций и распределение задач смотри в `README.md` и `UniFood_roles.md`.

Проект делают три студента CS. Код должен быть написан в студенческом стиле: простой и читаемый, без лишних абстракций, паттернов и «умных» приёмов. Должно быть видно, что проект создавали студенты.

## Стек

- Frontend: HTML5, CSS3, JavaScript (без фреймворков и сборщиков)
- Backend: PHP (без фреймворков)
- Реляционная БД: MySQL
- Нереляционная БД: MongoDB
- Запуск: Docker (`docker compose`)

Не добавляй библиотеки, фреймворки и сервисы, которых нет в этом списке, без явного разрешения пользователя.

## Структура проекта

```
docker/php/Dockerfile     образ PHP + Apache
database/init/            SQL-скрипты для первого запуска MySQL
public/                   корень веб-сервера (страницы, css/, js/, api/)
src/                      общий backend-код (config, подключения к БД, сессии, роли)
docker-compose.yml
composer.json
.env.example              пример настроек (реальный .env в репозиторий не попадает)
```

Backend-код, который не должен быть доступен из браузера, лежит в `src/`, а не в `public/`.

## Как писать код

- **Комментарии как в реальной разработке.** В начале каждого файла: назначение файла. У каждой функции: документирующий комментарий (для PHP формат PHPDoc) с описанием, параметрами и возвращаемым значением. Внутри кода комментируй, **почему** так сделано, а не пересказывай очевидное. В `Dockerfile` и `docker-compose.yml` комментируй нетривиальные настройки.
- Язык комментариев: русский.
- Имена переменных, функций, файлов и папок: английские, понятные.
- Обращения к MySQL только через подготовленные запросы (PDO). Пароли и ключи не записываются в код и не попадают в репозиторий.
- Роли пользователей называются `student`, `staff`, `admin` везде одинаково.
- Не пиши лишнего: делай только то, что просит пользователь в текущей задаче.

## Git и GitFlow

- Работай только в ветке текущей задачи (`feature/...`), созданной от `develop`. Какая ветка нужна, говорит пользователь.
- Не меняй ветки `main` и `develop`. Не делай слияния.
- **Не выполняй `git push`, не создавай Pull Request.** Это делает пользователь сам.
- Коммиты делай локально, небольшие и по смыслу (одна законченная часть работы: один коммит). Сообщения коммитов на русском, понятные.
- Не коммить `.env`, `vendor/`, служебные файлы системы и редакторов.

## Границы работы

- Делай только то, что указано в задаче. Ничего не добавляй «заодно».
- Не правь файлы, которые не относятся к задаче. Если для задачи нужно изменить чужой файл (общий код, общие стили, схему БД), остановись и спроси пользователя.
- Если требование неясно или противоречит этому файлу, не угадывай. Остановись и задай один уточняющий вопрос.
- Не удаляй и не переписывай существующий код без явной просьбы.

## Порядок работы над задачей

1. Сначала составь план действий и жди одобрения пользователя. Код не пиши.
2. После одобрения реализуй задачу по частям, после каждой части делай локальный коммит.
3. Проверь результат запуском в Docker. Если проверить нельзя, прямо скажи об этом. Не выдавай непроверенное за проверенное.
4. В конце выведи отчёт: что сделано, какие файлы созданы или изменены, результат проверки, в чём не уверен. Затем остановись и жди указаний.

## Договорённости между разработчиками

Общие имена и структуры данных, чтобы ветки не расходились. Если нужно поменять — сначала согласовать с владельцем.

### Роли и сессия

- Роли: `student`, `staff`, `admin`; константы `ROLE_*` лежат в `src/roles.php`.
- После входа в сессию пишутся `$_SESSION['user_id']` (int) и `$_SESSION['role']` (string).
- Проверки доступа: `isLoggedIn()`, `getCurrentUserRole()`, `requireLogin()` (код 401), `requireRole()` (код 403).
- Сессию стартуем только через `startSession()` из `src/session.php`.

### Таблица `users` (контракт для `feature/auth`)

Такую таблицу ожидает код авторизации; создаёт её Разработчик 2 в `database/init/`.

| Колонка | Тип | Назначение |
|---|---|---|
| `id` | `INT UNSIGNED AUTO_INCREMENT`, PK | идентификатор пользователя |
| `email` | `VARCHAR(255) NOT NULL UNIQUE` | логин, приводится к нижнему регистру |
| `password_hash` | `VARCHAR(255) NOT NULL` | результат `password_hash()` |
| `full_name` | `VARCHAR(100) NOT NULL` | имя пользователя |
| `role` | `ENUM('student','staff','admin') NOT NULL DEFAULT 'student'` | роль |
| `created_at` | `DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP` | дата регистрации |
