# ОТЧЁТ

## по результатам технического аудита веб-ресурсов

### по дисциплине «Разработка web-приложений»

**Тема:** технический аудит веб-ресурсов в предметной области предварительного заказа еды и самовывоза

---

# 1. Цель работы

Целью работы является проведение технического анализа существующих веб-ресурсов в предметной области заказа еды с последующим использованием полученных результатов при проектировании собственного веб-приложения **CampusFood**.

В рамках исследования были рассмотрены следующие характеристики веб-ресурсов:

* архитектура и логика работы;
* пользовательский сценарий заказа;
* клиентские и серверные технологии;
* HTTP-запросы и ответы;
* использование семантических элементов HTML5;
* использование `div` и CSS-классов;
* адаптивность;
* результаты Lighthouse;
* Cookies и Web Storage;
* инструменты веб-аналитики и маркетинга.

# 3. Методика исследования

Для проведения технического аудита использовались встроенные инструменты браузера DevTools.

Основные инструменты:

* **Elements** — анализ HTML-разметки;
* **Console** — подсчёт и проверка HTML5-элементов;
* **Network** — анализ HTTP-запросов и ответов;
* **Sources** — анализ подключаемых CSS и JavaScript-файлов;
* **Application / Storage** — анализ Cookies, Local Storage, Session Storage и IndexedDB;
* **Lighthouse** — оценка производительности, доступности, Best Practices и SEO.

Для исследования пользовательской логики выполнялся последовательный сценарий:

**главная страница → каталог → категория → карточка товара → корзина → выбор способа получения → оформление заказа.**

# 4. Terra Pizza

## 4.1. Общая характеристика

Terra Pizza представляет собой веб-ресурс для просмотра меню и оформления заказа еды.

Основными элементами пользовательского сценария являются:

1. просмотр каталога;
2. выбор категории;
3. просмотр карточки блюда;
4. добавление блюда в корзину;
5. просмотр и изменение корзины;
6. выбор способа получения;
7. выбор ресторана при самовывозе;
8. дальнейшее оформление заказа.

Ресурс содержит как функциональность доставки, так и самовывоза.

---

## 4.2. Архитектура и логика

Логика пользовательского взаимодействия построена вокруг каталога продукции и корзины.

Основной сценарий:

```text
Главная страница
      ↓
Каталог
      ↓
Категория
      ↓
Карточка блюда
      ↓
Добавление в корзину
      ↓
Корзина
      ↓
Способ получения
      ↓
Самовывоз
      ↓
Выбор ресторана
      ↓
Оформление заказа
```

При взаимодействии с каталогом пользователь может последовательно переходить от общей информации к конкретному товару, после чего товар добавляется в корзину.

---

## 4.3. Технологический стек

На клиентской стороне используются:

* HTML5;
* CSS3;
* JavaScript;
* сторонние JavaScript-библиотеки и сервисы.

HTML отвечает за структуру страницы, CSS — за визуальное представление и адаптивность, JavaScript — за интерактивные элементы и динамическое взаимодействие с сервером.

Серверная часть взаимодействует с клиентом посредством HTTP-запросов.

---

## 4.4. HTTP-запросы

При работе с каталогом и корзиной в Network наблюдаются HTTP-запросы, связанные с загрузкой данных и изменением состояния пользовательской сессии.

Особое внимание уделялось запросам Fetch/XHR.

Исследовались:

* HTTP-метод;
* URL;
* статус ответа;
* заголовки;
* передаваемые параметры;
* тело ответа.

При выполнении действий пользователя изменяется набор сетевых запросов, что свидетельствует об использовании динамического взаимодействия клиентской части с сервером.

---

## 4.5. Семантический HTML5

В структуре страницы используются семантические элементы HTML5.

| Элемент   | Назначение                   |
| --------- | ---------------------------- |
| `header`  | верхняя часть страницы       |
| `nav`     | навигационные элементы       |
| `main`    | основное содержимое          |
| `section` | логические разделы           |
| `footer`  | нижняя часть страницы        |
| `form`    | ввод пользовательских данных |

Кроме семантических элементов широко используются контейнеры `div`.

---

## 4.6. Использование `div` и CSS-классов

Для построения интерфейса применяются `div` с классами, описывающими назначение элементов.

Основные типы компонентов:

* контейнеры каталога;
* карточки товаров;
* элементы корзины;
* блоки навигации;
* элементы оформления заказа.

Использование классов позволяет разделить структурные и визуальные свойства элементов и повторно использовать одни и те же стили для однотипных компонентов.

---

## 4.7. Адаптивность

Веб-интерфейс адаптируется под различные размеры экрана.

При уменьшении ширины окна:

* изменяется расположение элементов;
* перестраиваются карточки товаров;
* изменяется навигация;
* изменяются размеры некоторых компонентов интерфейса.

Для реализации адаптивного поведения используются CSS media queries.

---

## 4.8. Lighthouse

Для оценки веб-ресурса использовался Lighthouse.

Проверялись:

* Performance;
* Accessibility;
* Best Practices;
* SEO.

Результаты занесены в таблицу технического аудита с указанием условий проведения тестирования.

---

## 4.9. Cookies и Web Storage

В процессе анализа Application/Storage исследовались:

* Cookies;
* Local Storage;
* Session Storage;
* IndexedDB.

Cookies используются веб-ресурсом для хранения данных, связанных с работой сайта и пользовательским сеансом.

Также анализировалось наличие данных в Web Storage.

---

## 4.10. Аналитика

Network использовался для поиска запросов, связанных с системами аналитики и маркетинга.

Проверялись ключевые слова:
